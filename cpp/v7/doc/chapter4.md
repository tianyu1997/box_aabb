Lifelong envelope cache tree
4.1 设计原则
    机器人的link interval envelope 只与其本身运动学相关，与环境无关，因此可以设计一个**终身缓存**（lifelong cache）来存储link interval envelope，供整个规划过程反复查询使用。
    但是7dof的机器人关节空间维度较高，缓存想要覆盖任意interval是不可能的，因此需要设计一个**KD tree结构**来组织这些缓存。树的每个节点对应一个区间，存储该区间的link interval envelope；子节点对应更小的区间，存储更精细的包络信息。查询时根据需要递归访问树节点，直到找到满足精度要求的包络。
4.2 best tigeten kd tree
    切分维度时，选择对包络体积贡献最大的关节维度进行切分，以最大程度提升包络紧致度。（具体实验方式参考代码总结）
4.3 随着切分深度增加的父节点包络优化
      直接计算一个区间的包络松散度是很大的，包络体积大于将该区间细分成更小区间的包络体积之和。所以每当一个节点被切分成两个子节点时，可以对父节点的包络进行优化，使其更紧致。具体方法是取两个子节点的包络并集作为新的父节点包络。这样可以显著减少父节点包络的体积，提高缓存的效率和查询性能。
4.4 储存结构
      4.4.1 kd tree Z4对称性
            由于机器人关节空间具有周期性（例如旋转关节每360度重复），可以利用这种对称性来减少缓存的存储需求。对于周期性维度，可以只存储一个周期内的包络信息，查询时根据输入的区间自动映射到对应的周期内进行查询。这样可以大幅减少缓存的大小，同时提高缓存命中率。
      4.4.2 树的mmap设计
            由于缓存树可能非常大，无法一次性加载到内存中，因此需要设计一个mmap机制来存储缓存数据。可以将缓存树的数据结构序列化为一个二进制文件，并使用mmap将其映射到内存中。这样可以实现按需加载和访问缓存数据，避免一次性加载整个树导致的内存占用过高问题。同时，mmap还可以提供高效的随机访问性能，满足规划过程中频繁查询缓存的需求。
      4.4.3 lazy load 设计
            由于缓存树可能非常大，无法一次性加载到内存中，因此需要设计一个lazy load机制。只有当查询请求访问到某个节点时，才加载该节点的数据到内存中。可以使用一个LRU（最近最少使用）策略来管理内存中的缓存数据。
      4.4.4 incremental save设计
            在规划过程中，缓存树会不断被访问和更新。为了避免每次更新都需要重新保存整个树，可以设计一个增量保存机制。只有当某个节点的数据发生变化时，才将该节点的数据保存到磁盘上。这样可以大幅减少磁盘I/O的开销，提高整体性能。
